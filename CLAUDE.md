# EVRST — repo guide for Claude

Monorepo for the **Escape Velocity Rocketry Student Team** site.

```
.
├── frontend/   Vue 3.5 + PrimeVue + Pinia + Vite SPA, package manager: bun
├── backend/    Laravel 12 + Filament v4 admin, SQLite
├── .github/    Dokku deploy workflow (tag-driven)
├── .buildpacks heroku-buildpack-nodejs @ master + dokku/heroku-buildpack-nginx
├── CHANGELOG.md
└── .claude/skills/{evrst-frontend,evrst-backend}/SKILL.md
```

When working on the SPA, follow `.claude/skills/evrst-frontend/SKILL.md`.
When working on the API/admin, follow `.claude/skills/evrst-backend/SKILL.md`.
The README at the repo root has the public-facing tour of features
(roles, applications flow, tasks, kanban, mailer/queue env).

## Run locally

```sh
# Backend (port 8000)
cd backend && composer install && cp .env.example .env && php artisan key:generate && php artisan migrate --seed && php artisan serve

# Backend queue worker (separate terminal — needed for member-application
# admin notifications + Discord webhook posts; QUEUE_CONNECTION=database)
cd backend && php artisan queue:work --tries=3

# Frontend (port 5173 — falls back to 5174/5175 if busy)
cd frontend && bun install && bun run dev
```

Admin login: `admin@evrst.test` / `password` at `http://localhost:8000/admin`.
Frontend `.env` already points `VITE_API_URL` at `http://localhost:8000/api`.

## Branching + commits

- Feature work goes on `feature/<version>` branches (currently `feature/0.4.0`).
- **Small, single-responsibility commits** with conventional prefixes: `feat:`, `fix:`, `chore:`, `refactor:`, `perf:`, `docs:`, `style:`, optional scopes like `feat(home):`, `chore(backend):`.
- Never push to `main` directly. Never `git reset --hard` or `git push --force` without explicit permission.
- Never `--no-verify` / `--no-gpg-sign` etc. Investigate hook failures, don't bypass them.
- Don't commit without an explicit ask.

## Deploy

**Current target: Hetzner, via `compose.yaml`.** One VM, one domain. Caddy (`deploy/Caddyfile`) serves the built SPA at `/` and reverse-proxies `/admin`, `/api`, `/livewire`, `/storage`, `/css|js/filament`, `/up` to the Laravel container. Four services: `backend` (owns the schema — `RUN_RELEASE_TASKS` defaults to 1 so it alone runs migrate+seed on boot), `queue` (`queue:work`), `scheduler` (ticks `schedule:run` every 60s), `web` (Caddy + TLS). SQLite + `storage/` live on the `app-data` volume. Env comes from `backend/.env.production` (gitignored; copy `backend/.env.production.example`) plus `SITE_ADDRESS` in the repo-root `.env`. Guides: `deploy/README.md`, `deploy/HETZNER.md`, `deploy/DNS.md`.

Two stale deploy paths are still in the tree — don't assume either works:
- `.github/workflows/deploy.yaml` pushes the SPA to Dokku on a `v*` tag. Its version check reads `./package.json`, which **does not exist** at the repo root, so the job fails before deploying. Either repoint it at `frontend/package.json` or delete it.
- `deploy/fly/fly.toml` is a parked Fly.io config. It predates the compose stack and, unlike `compose.yaml`, does **not** set `RUN_RELEASE_TASKS=0` on its `worker` process group — both process groups would run `migrate` against the same SQLite file. Fix that before ever using it.

## Common gotchas (carried over from past sessions)

- The Vite dev server may pick a non-default port (5174/5175) if 5173 is held — read the actual port from the server log before opening the browser.
- The harness blocks long-running web servers unless the user has approved them; if a `php artisan serve` / `bun run dev` background task is denied, surface the blocker rather than retrying.
- The Heroku buildpack we deploy with detects `bun.lock` only at recent versions — `.buildpacks` pins `@master` for that reason; do not pin to a specific commit without checking.
- The Heroku buildpack will run `npm run build` if it can't detect bun, so don't rely on `bun:` prefixed scripts in `frontend/package.json`.
- **Frontend is Vue 3, not React** (rewritten in 0.5.2, redesigned in 0.6.0). Build runs `vue-tsc --noEmit --skipLibCheck && vite build`. Auto-imports + auto-component registration are handled by `unplugin-auto-import` + `unplugin-vue-components`; the generated `.d.ts` files appear after the first `vite build`/`dev` run, so a freshly cloned tree must build once before `vue-tsc` succeeds.
  **This bites on every new auto-imported composable**: `bun run build` type-checks BEFORE it builds, so it can never regenerate the `.d.ts` that would make it pass. Run `./node_modules/.bin/vite build` once, then `bun run build`.
- Vue rewrite removed Mantine, TanStack Query, react-icons, MDX, react-three-fiber, react-router. The 0.6.0 redesign then removed **PrimeVue + @primevue/themes** (156 KB gz; the join-us page went 171 KB → 9 KB), **Three.js** (the hero is SVG + CSS parallax now), `vue-formify`, `maska` and `@unocss/transformer-directives`. What is left: `motion-v`, `pinia`, `vue-router`, `vue-i18n`, `@vueuse/core`, `date-fns`, `@sentry/vue`, UnoCSS + SCSS, and the custom `useQuery` composable. Design plan and every decision behind it: `docs/frontend-redesign.md`.
- SCSS breakpoint mixin map starts at `xs: 0`. Don't pass `xs` to `media-down(...)` — Sass rejects `calc(0 - 1px)`. Use `media-down(sm)` for "below sm".
- `MAIL_MAILER=log` is the default in `.env.example`. The temp passwords sent by the Accept-application / Create-user / Resend-temp-password actions land in `backend/storage/logs/laravel.log` (queued through the database queue worker). Switch to Postmark/Resend (env keys are scaffolded in `config/services.php`) for real email delivery.
- **Team logins are org addresses.** Members sign in with `<given>.<surname>@evrst.hu` (`App\Support\OrgEmail`), stored in both `users.email` and `team_members.email`. Delivery is decoupled: `MAIL_DELIVER_TO_ORG=false` (default) sends to `team_members.email_private`. **Decision 2026-09-08: that stays false — `@evrst.hu` is a login only, permanently.** No mailboxes, aliases or catch-all at Websupport; mail *to* an org address bounces, and nothing in the app sends there. Don't print an org address as a contact address anywhere. Flipping to `true` requires creating mailboxes first. Always resolve the recipient via `User::deliveryEmail()`. Full guide + rollout checklist: `docs/org-email-logins.md`.
- **Onboarding the roster is a bulk action.** Users table → select rows → **Send temp password** (`UsersTable::sendTempPasswords()`). `TeamSeeder` mints passwords but deliberately does *not* email them (spam on every reseed) — it writes them to `storage/app/seeded-team-passwords.txt`. The bulk action **skips** anyone whose `deliveryEmail()` resolves to an `@evrst.hu` address while `MAIL_DELIVER_TO_ORG=false`, because rotating a password we can't deliver locks the member out. Nyári György + Som Nemere have no `email_private` and are exactly that case.
- **Adding a team member provisions their login.** The Team members create page (admin only) runs `App\Support\MemberLogin::provision()` in `afterCreate()`: derives the org address from the name when the field was left blank, creates a Member-role `User` with `password_changed_at = null`, links `team_members.user_id`, and `sendNow`s the temp password to `deliveryEmail()`. Skipped when the row already has a user or `left_at` is filled; a manager (who has `team.create` but not Users access) gets a "no login created" warning instead. The same service backs the **Create login** button on the member edit page and `php artisan team:provision-login {id|email|name}` (`--all`, or no argument to list rows with no login) for the deploy box. No mail is sent when the only address on file is the `@evrst.hu` login — the account is still created and reported. Not an observer: `TeamSeeder` writes straight to the table and would mail the whole roster on every reseed.
- **Temp passwords have exactly one exit.** `App\Actions\IssueTempPassword` — `rotate($user)` for an existing account, `deliver($user, $password)` for a fresh one. It resolves the destination via `deliveryEmail()`, refuses an undeliverable address *before* rotating, rolls the old hash back if the send throws, and returns a `TempPasswordResult`; `App\Filament\Support\TempPasswordReport::flash()` / `flashBatch()` turn that into the panel notification. All five call sites (Users row action + bulk, Create login, CreateUser, accept-application) go through it — don't hand-roll a sixth.
- **Tasks: `tasks.progress` vs `tasks.edit`.** `Task::canBeProgressedBy($user)` is the per-record gate behind `TaskResource::canEdit()`, `canTransitionTo()` and the kanban: `tasks.edit` opens any task, `tasks.progress` (the Member role) opens one you are assigned to or supervise. `TaskForm::definitionLocked()` disables the definition fields for the second group, so they can attach proof and move the status without rewriting the task. Added by `2026_09_09_000001_attach_tasks_progress_permission`.
- **Calendar is read-all, write-admin.** `Calendar::canManageEvents()` plus an `abort_unless` at the head of every mutating Livewire method — the Blade only hides the affordances, and a Livewire endpoint is reachable regardless of what was rendered.
- **Items stay open on purpose.** Everyone signed in can edit the catalog and the stock table; the trade is `/admin/item-log` (`App\Filament\Pages\ItemLog`), which surfaces the `Item` / `ItemStock` slice of `activity_logs` to the same audience. The full audit feed under Membership → Activity log stays admin-only.
- **`RequirePasswordChange` runs on the `web` group too** (`bootstrap/app.php`), not just the panel's `authMiddleware`: `/livewire/update` is a plain `web` route, so the gate never saw component updates. Its Livewire allow-list is by component *name*, resolved from the classes via Livewire's `ComponentRegistry` — profile + notification components only, so an unactivated user can't drive global search from the profile page's topbar.
- **Panel assets must be routed to the backend in `deploy/Caddyfile`.** Anything the panel requests that the `@backend` matcher misses falls through to the SPA handler, whose `try_files` answers `index.html` — a 200 of the wrong content type, so the browser drops it silently with nothing in the console. The matcher needs `/css/admin-theme.css` (the mission-console sheet — without it the panel is plain text on black), `/fonts/filament/*` (Filament's Inter face; matched on the `/filament/` segment because the SPA serves its own Panchang from `/fonts/`) and `/vendor/*` (SortableJS, which the kanban needs). Anything new under `backend/public/` needs the same treatment — grep for `asset(` in `resources/views/` and `app/Providers/` to find them.

- **The join-us form is data, not code.** Questions live in `application_form_fields` (grouped by `application_form_sections`) and are edited under Membership → Application form. `App\Support\ApplicationForm` is the single reader: `schema()` feeds `GET /api/application-form` (which the SPA renders from), `rules()` generates the validation for `POST /api/member-applications`, and `split()` puts `name`/`email` in columns and everything else in `member_applications.answers` keyed by field key. `name` + `email` are `is_system` — relabel and reorder them, but they cannot be deleted, re-keyed or hidden, because the accept flow provisions a login from them. A field's `key` is write-once: it is what every collected answer is filed under. The seeded form reproduces the old hardcoded one field for field, installed by a migration as well as `ApplicationFormSeeder` because `db:seed` runs only once per volume.

- **Notification mail is localized two ways.** `User` implements `HasLocalePreference` (→ `users.locale`), so notifications render in the recipient's chosen language. Body copy is `lang/{en,hu}/admin.php` under `mail.*`. Laravel's own chrome (`Regards,`, the trouble-clicking subcopy, the entire built-in password-reset email) are **JSON** keys, so they live in `lang/hu.json` — without that file HU members get Hungarian text in English framing. A member with `locale = null` renders in `APP_LOCALE` (`en` by default) because the queue worker has no session.
- **`APP_URL` must be right in production.** The task notifications are `ShouldQueue`, so `TaskResource::getUrl()` renders in the worker with no request in scope and falls back to `config('app.url')` — get it wrong and every "Open task" link in every email points at localhost.
- Filament's login screen has **Forgot password?** enabled (`->passwordReset()`), and a completed reset stamps `password_changed_at` (listener in `AppServiceProvider`) so it also clears the `RequirePasswordChange` gate.
- The seeded `admin@evrst.test` has `password_changed_at` pre-stamped so it never trips the first-login redirect. Every other user provisioned through the admin must set a new password before reaching any admin page.
- Switch to a real mailer to actually deliver temp passwords: in `backend/.env` set `MAIL_MAILER=resend` plus `RESEND_API_KEY=...` (or `MAIL_MAILER=postmark` + `POSTMARK_API_KEY=...` — both have config stubs in `config/services.php`). Local dev keeps `MAIL_MAILER=log` so the password lands in `storage/logs/laravel.log`.
- LAN-accessible dev: backend launches with `php artisan serve --host=0.0.0.0 --port=8000`; the SPA is bound to `0.0.0.0` via `frontend/package.json`'s `"dev": "vite --host 0.0.0.0"`. `frontend/.env` `VITE_API_URL` plus `backend/.env`'s `APP_URL` + `ADMIN_URL` need updating if your LAN IP changes.
- Activity log lives in `activity_logs` and is populated by `App\Concerns\LogsActivity` (mounted on `Resource`, `Task`, `MemberApplication`, `Drawing`, `OnshapeModel`, `CalendarEvent`, `TaskProof`). Visible to Admins under Membership → Activity log; not surfaced to Manager/Member.
- The trait now exposes `logActivity($event, $changes)` for hand-shaped entries (e.g. `'accepted'` / `'rejected'`) and `withoutActivityLog($cb)` for suppressing the auto-log inside a single transaction. Used by the application accept/reject flow and by the kanban bulk reorder so dozens of position changes don't dump dozens of "updated" rows.
- Activity log retention: a daily `php artisan activity-log:prune --days=90` job is scheduled in `routes/console.php` (03:15 every night, `onOneServer + withoutOverlapping`). Anything older than 90 days is removed.
- Public images go through `/api/img?path=…&w=…&f=webp` (intervention/image v4 + GD). Variants are cached under `storage/app/public/cache/img/{prefix}/{hash}.{ext}` (gitignored by the existing public-disk gitignore) and pruned by `image-cache:prune --days=30`, scheduled at 03:30 nightly. SVG + animated GIF requests pass through to the original bytes. The SPA's `<ResponsiveImage path=…>` + `lib/imgUrl.ts` (`imgUrl()`, `pathFromStorageUrl()`) consume both `/api/img` and `/api/img/meta` (which returns intrinsic dimensions + a 24px webp LQIP data URI).
- Roles + permissions are seeded via `Perm::catalog()` but admins can rebalance them at runtime in Filament: Membership → Roles & permissions. Code-side perm checks still drive visibility — flipping perms in the UI takes effect on the next request.
- **When you add new `Perm::*` keys**: write a one-shot migration that inserts the rows into `permissions` and attaches them to `roles` (via `permission_role`), like `2026_05_03_000007_attach_models_permissions.php`. Existing seeded roles do NOT pick up new keys from `Perm::catalog()` automatically because `RoleSeeder` runs once.
- The kanban (`/admin/tasks/kanban`) disables drag-and-drop while filters are active to avoid rewriting `position` over a partial set; the page shows a banner explaining why.
- SortableJS is vendored at `backend/public/vendor/sortable.min.js` so the kanban works without internet access.
- **Discord mentions are snowflake-gated.** `App\Support\DiscordPayloads::mention()` only emits a real `<@id>` ping when `discord_id` matches `^\d{17,20}$`. Otherwise it falls back to plaintext `@discord_nick`, then `@discord_username`, then `user.name` — so the channel never shows broken `<@username>` markup. `wantsDiscordPing()` returns true when the user has any of nick / username / id.
- **Discord bot DM scaffolding exists but is dormant.** `App\Services\DiscordBot` + `App\Jobs\SendDiscordDirectMessage` no-op until `DISCORD_BOT_TOKEN` is set in `.env` (and the snowflake is populated). Channel webhook (`SendDiscordWebhook`) remains the only live outbound path; `CreateTask` / `EditTask` / `KanbanBoard` / `CommentsRelationManager` still dispatch the webhook per recipient. Once a bot is registered + snowflakes collected, swap those dispatches for `SendDiscordDirectMessage::dispatch(...)`.
- **The document must be the scroll container.** `overflow-x: hidden` on `body` (with `height: 100%`) makes BODY the scroller — one axis going non-visible forces the other to `auto`. Everything scroll-driven then dies silently: `animation-timeline: scroll(root block)` tracks the root, which never scrolls, so every scroll animation freezes at its start state; `window.scrollY` stays 0, so the JS fallback dies too; and the chrome's surface sampling, the back-to-top threshold and the pill's mobile reveal all read `scrollY`. `src/styles/_base.scss` uses `overflow-x: clip` on `html` instead — `clip` suppresses overflow WITHOUT creating a scroll container. **If a scroll-driven animation appears not to run at all, check what is scrolling before checking the animation.**
- **`@` in a vue-i18n message value is linked-message syntax.** `email: 'evrstrocket@gmail.com'` throws `Message compilation error: Invalid linked format` at compile time and takes down every component that reads any key in that file. The email lives in `src/lib/site.ts` as a constant — it is not translatable content anyway. Anything else containing a literal `@` needs `{'@'}`.
- **The hero is a sticky stage, not a tall box.** `Hero/layers.ts` owns `STAGE_VH` (3.0) and `PIN_VH`; the pane is `position: sticky; height: 100dvh` inside it, and `--pin` is a **dvh length**, not a measured px. Binding a measured value meant `--pin: 1px` on the first paint, which put every scroll-driven animation at its END state for one frame. Pin duration is a content measurement — it is however long the sequence inside it takes.
- **`useSurfaceMode` has three modes, not two.** `light` / `dark` / `brand`. feat.agency folds its brand colour into `dark` because its wordmark sits on a white card; EVRST's gold IS the lettering, so gold-on-gold over the sponsor pitch panel made the mark vanish. `brand` sends the whole wordmark to ink and wins the three-sample vote outright. Put `surface-ignore` on any decorative overlay whose background must not decide the chrome's colour.
- **Every routed page needs a single ELEMENT root.** `App.vue` wraps `<RouterView>` in `<transition name="router-fade" mode="out-in">`, and `out-in` waits for the outgoing page's leave transition before mounting the incoming one. A fragment root (two top-level nodes) or a `v-if` chain with no `v-else` (which renders a comment node) gives it nothing to run that transition on, so the wait never ends and the next page never mounts — `<main>` just goes empty. That was the join-us → home bug: `JoinUsPage` was `<HtmlTitle>` + `<SectionShell>`. Vue logs `Component inside <Transition> renders non-element root node that cannot be animated`; if a navigation blanks the page, check the console for that line first.
- **`useQuery` writes a placeholder cache entry before it decides whether to fetch.** So "is there a cache?" must be `getCache(key)?.data !== undefined`, NOT `hasCache(key)` and NOT the entry's `meta.time` — both are true/now for the placeholder the same call just wrote. Getting that wrong made every `cache: true` query treat its own empty placeholder as a warm hit and return without ever fetching: the entire site sat on its skeletons and the sections that count rows rendered `0 members · 0 groups`. `useQuery.ts` reads the cache into `warm` / `isHit` before the placeholder is written, and both cache branches test `isHit`.
- **The bottom nav band is `pointer-events: none`; only the pill takes clicks.** `<nav class="nav">` is `inset-x-0` — a full-width strip that exists only to centre the pill — and it is `--z-nav` (100), above the back-to-top rocket at `--z-float` (90). At the same height, every click aimed at the rocket landed on the empty band instead and the button silently did nothing. Anything else parked in that bottom row will hit the same wall.
- **Full-bleed section art goes in `SectionShell`'s `bleed` slot, never the default one.** The default slot renders inside `.container` (max-width 1440 plus a gutter), so a `position: absolute; inset: 0` background laid out there stops short of both page edges and paints a visible rectangle of itself — and a `radial-gradient(... at 50% ...)` inside it is centred on the container, not the viewport, which reads as an off-centre gradient. The `bleed` slot renders inside `<section>` and above nothing; `.container` carries `z-index: 1` so content always wins.
- **`--paper` is an INK, `--paper-surface` is a GROUND.** `--paper` (#f8f7f4) is the wordmark's light half and the label colour on dark buttons — it must stay that bright. `--paper-surface` is what the one inverted section paints, and it is deliberately darker (#e7e4dc): at the ink value the jump from `--ink-0` was a 19:1 step across a single hairline and the team section read as a different site. Don't collapse them back into one token. Softening that edge with a gradient does not work either — `surfaceModeAt` decides the wordmark's colour from the first opaque `background-color` under it, so it cannot see a gradient and the mark flips to ink while still over black.
- **Panchang's `ch` unit is useless.** Its zero is 1.19em wide, so `max-width: 26ch` on display type resolved to 1737px — wider than the viewport it was meant to constrain. Use `em` for a measure on anything set in `--font-display`.
- **The hero's overscan is DIRECTIONAL, and the depth signs all agree.** In `Hero/layers.ts`, positive depth descends and negative climbs; the ground descends (near fastest), the rocket climbs, and the copy layer is 0 because the statement sequence rides it and must hold the viewport's centre. A layer only gets overscan on the edge it travels towards (`overscanFor` returns `{top, bottom}`) — applying it to both made the near ridge a 340dvh composited box to carry a 120px ridge line. What sells the speed is not travel: it is the two star planes zooming at different rates and stretching on Y, which turns the dots into streaks with no second asset and no repaint — and the zooms are deliberately small (1.18 / 1.36), because the eye reads the DIFFERENCE between two rates, not the size of either, and at 1.42 / 2.1 it read as flying into the field rather than past it.
- **A masked per-character split costs ~2% of line width.** Every glyph becomes its own inline-block in `components/Motion/SplitText.vue`, so kerning pairs stop applying and each advance rounds up. `--fs-display` was reduced to leave headroom for it; a display line sized to fit its container exactly will wrap once it is split.
- **A stale UnoCSS colour utility fails silently.** The 0.6.0 redesign renamed the theme to `ink` / `gold` / `paper` / `txt`, and an unknown utility emits no CSS rather than erroring — so `bg-primary text-bgDark` on `EvrstMarquee` quietly dropped the page's one gold band to white-on-black and nobody saw a warning. `grep -rE '(bg|text|border)-(primary|bgDark|bgGray|cardBg|cardBorder|cardBorderAccent)\b' src` finds the rest; it is clean as of this pass.
- **A seamless CSS marquee needs two EQUAL rows and a gap that belongs to the row.** Animating one track of N copies by `-100/N%` can never line up, because the gaps between copies belong to the track: a third of the track's width is not a copy's advance, and the strip jumps by the difference every cycle. Two identical rows, each with its own internal `gap` AND a trailing `padding-right` of the same size, animated to `-50%`, makes half the track exactly one row. The second requirement is that ONE row is wider than the viewport — otherwise the tail of the travel runs out of content before the screen ends.
- **The document does not rubber-band.** `overscroll-behavior-y: none` on `html` in `_base.scss`. The hero's sky is painted on the section, not on the page ground, so bouncing past the top exposed `body`'s flat `--ink-0` as a black bar sliding over the artwork. `contain` is not enough — it stops scroll chaining, not the bounce.
- **`main` reserves a viewport (`min-height: 100dvh`).** Every route is a lazy `import()`, so on a cold load `<main>` is empty until the chunk lands; without the reservation the footer renders at the top of the screen and is then shoved a whole hero out of the way.
- **The hero's build waits for `document.fonts.ready`** (with a 1.5s timeout so a font failure cannot leave it blank). The copy block is vertically centred and `font-display: swap` changes both its height and its line wraps, so every line moves when Panchang lands. The space is reserved throughout — the block is laid out the whole time, just at opacity 0 behind its masks.
- **The launch tower is painted BEFORE the mid ridge, not after.** It used to stand on a number (108px up from the pane's bottom) while the ridge line under it is wherever the clip-path polygon happens to be at the tower's x — about 60px — so it hung in mid-air. Ordering it behind the ridge lets the ridge's own fill bury the feet at every viewport width with no number to keep in sync.
- **Ambient loops stop when their block leaves the screen** — `composables/useOffscreenIdle.ts`, used by the hero and the marquee. The point is not the ticks: a running animation keeps its element promoted to a compositor layer, and the marquee's track is a ~6900px-wide texture held for a page it is visible on for one viewport in nine. Only CSS animations respond to `animation-play-state`; motion-v's are WAAPI and unaffected, which is the right scope. Never blanket-pause the hero with `:deep(*)` — that would freeze the scroll-driven parallax at wherever it left the frame.
- **`--gold-700` exists because `--gold-600` is not text on paper.** 2.1:1 against `--paper-surface`; `--gold-700` clears 4.5:1. Used by the eyebrow and the roster counts inside a paper section, nowhere else — on ink, `--gold-500` is already 10:1.
- **Mono-uppercase is the DATA voice.** Eyebrows, counts, specs, group legends. A person's job title is content, so the roster's `<small>` is set in the body face — as mono-uppercase it was indistinguishable from the group heading above it and "ELECTRICAL ENGINEER" read as the start of a new group.
- **Every save in the panel returns to the table**, set once on the panel: `->resourceCreatePageRedirect('index')` + `->resourceEditPageRedirect('index')` in `AdminPanelProvider` (Filament v4.11 API — `Filament::getResourceCreatePageRedirect()` is what the base pages consult). Don't do this with a per-page `getRedirectUrl()` trait; 36 pages was the first attempt and the panel setting replaced all of it. A page that genuinely needs to stay after a save still opts out by declaring its own `getRedirectUrl()`.
- **The roster row and the panel account are one lifecycle, and `App\Support\MemberLogin` owns all three directions.** `provision()` roster → account (unchanged), `revoke()` member deleted → account deleted, `detach()` account deleted → member survives. The two new ones are wired to model events (`TeamMember::deleted`, `User::deleting`) rather than to the Filament actions, because there are four ways to delete a row — row action, bulk action, edit-page header button, shell — and any of them leaving an account behind means someone who can still sign in while appearing nowhere. `provision()` stays out of the events on purpose: `TeamSeeder` would mail the whole roster on every reseed. The seeder is safe from the new hooks because it wipes with `TeamMember::query()->forceDelete()`, a mass delete on the query builder, which fires no model events.
- **`revoke()` refuses two accounts: your own and any admin's.** Deleting the account you are signed in as ends the request at the login screen halfway through a bulk action; deleting an admin's because someone tidied the roster can lock the panel. The roster is a list of people, not an authorisation list.
- **`User::deleting`, not `User::deleted`.** `team_members.user_id` is `nullOnDelete`, so by the time `deleted` fires the database has already broken the link and `$user->teamMember` — a `where user_id = ?` — finds nothing. The member would keep `is_public = true` and stay on the public site with no account behind it. This cost one round of red tests; don't move it back.
- **Deleting a user unpublishes their member row rather than filtering the API.** `is_public = false` + `user_id = null`, so the change is visible and reversible in the panel, "Create login" reappears on the row, and a member who legitimately has no login can still be published.
- **"Create login" exists on the team members TABLE as well as the edit page** — it is the route back after deleting an account, and it should not require opening the record. The notification wording moved out of the `ProvisionsMemberLogin` page trait into `App\Filament\Support\MemberLoginReport` (a sibling of `TempPasswordReport`) because a table action's closure cannot reach a page trait's protected methods.
- **Tests must never produce real outbound traffic.** Use `Notification::fake()` / `Mail::fake()` / `Bus::fake()` / `Http::fake()` in every feature test. `phpunit.xml` already forces `DISCORD_WEBHOOK_URL=""`, `DISCORD_BOT_TOKEN=""`, and `MAIL_MAILER=array` as a safety net, but the fakes are still required so a stray queued job doesn't try to hit the network.
