## 3. Resend API key  ⏱ 5 perc

A domain **már verifikált** a Resendben (a DKIM és a return-path MX élnek, lásd
`org-email-logins.md` §5) — csak a kulcs kell.

**Ha szerinted már létezik a kulcs és be is van állítva**, ne hozz létre újat — ugorj a
6. lépésre és futtasd a `mail:doctor`-t. Az megmondja, hogy a konténer látja-e, és hogy
a Resend elfogadja-e. Új kulcs létrehozása feleslegesen érvényteleníti a régit, ha
ugyanazt a nevet használod.

Ha viszont kell:

1. resend.com → **API Keys** → *Create API Key*.
2. Permission: **Sending access** elég a levélküldéshez. Tudni kell viszont, hogy egy
   ilyen kulcs a domain-listázást (`GET /domains`) nem tudja — a `mail:doctor` Provider
   blokkja ezért HTTP 401/403-at kap és „inconclusive"-ot ír. Ez **nem hiba**. Ha azt
   akarod, hogy a domain státuszát is ellenőrizni tudja, válaszd a **Full access**-t.
3. Másold ki a `re_...` kulcsot. Csak egyszer látszik.

A kulcs érvényességét mindenképpen a valódi küldés dönti el:
`php artisan mail:doctor --send=sajat@cimed.hu`.

A domain `Verified` státuszát nem kell kézzel néznie: a `mail:doctor` lekérdezi a
Resend API-tól, és kiírja minden domain státuszát. (A DNS oldala már rendben van.)

## 4. `backend/.env.production` a szerveren  ⏱ 10 perc

A szerveren (Hetzner VM), a repo gyökerében:

```sh
cp backend/.env.production.example backend/.env.production   # ha még nincs
```

Töltsd ki / ellenőrizd ezeket:

| Kulcs | Érték | Miért |
| --- | --- | --- |
| `APP_KEY` | `base64:...` | üresen a konténer szándékosan nem bootol |
| `APP_URL` | `https://evrst.hu` | **kritikus** — lásd lentebb |
| `ADMIN_URL` | `https://evrst.hu/admin` | Discord üzenetek linkjei |
| `RESEND_API_KEY` | `re_...` | a 3. lépésből |
| `MAIL_MAILER` | `resend` | a példafájlban már ez van |
| `MAIL_FROM_ADDRESS` | `"no-reply@evrst.hu"` | a példafájlban már ez van |
| `MAIL_DELIVER_TO_ORG` | `false` | a példafájlban már ez van |
| `DISCORD_WEBHOOK_URL` | a webhook URL | **a példafájlban ÜRES** — lásd lentebb |
| `QUEUE_CONNECTION` | `database` | a példafájlban már ez van |

`APP_KEY` generálása:

```sh
php -r 'echo "base64:".base64_encode(random_bytes(32)), "\n";'
```

### Miért kritikus az `APP_URL`

A task-értesítők `ShouldQueue`-k, tehát a queue workerben renderelnek, ahol **nincs HTTP
request** — a `TaskResource::getUrl()` a `config('app.url')`-re esik vissza. Ha rossz,
minden „Feladat megnyitása" gomb minden emailben `http://localhost`-ra mutat.

Az ideiglenes jelszós levél ettől független (az admin requestjéből, `sendNow`-val megy,
és van fallbackje), de nincs okod erre hagyatkozni.

### A Discord webhook nem öröklődik

A `PostDiscordWebhook` job **csendben no-opol**, ha a `DISCORD_WEBHOOK_URL` üres — nem
hibázik, csak nem történik semmi. A `.env.production.example`-ben üres. Ha azt akarod,
hogy a Discord megmaradjon (ezt kérted), másold be a webhook URL-t a lokális
`backend/.env`-ből.

### Caddy domain

A repo gyökerében külön env kell a compose-nak:

```sh
cp .env.example .env      # SITE_ADDRESS=evrst.hu már benne van
```

Ha `www`-t is akarsz: `SITE_ADDRESS="evrst.hu www.evrst.hu"`.


A leggyakoribb ok az `APP_KEY` (a konténer explicit `FATAL`-t ír, ha üres vagy rossz
formátumú).

## 6. Ellenőrzés élesítés előtt  ⏱ 5 perc

Sorban, a szerveren:

```sh
curl -fsS https://evrst.hu/up && echo "  health OK"
```

Aztán böngészőből:

1. `https://evrst.hu` → betölt a SPA.
2. `https://evrst.hu/admin` → Filament belépő.
3. Lépj be az adminnal (`admin@evrst.test`). Ez a fiók `password_changed_at`-je előre
   ki van pecsételve, tehát nem esik bele a kényszerített jelszóváltásba.
4. **Membership → Users** → nézd meg a *Levél ide megy* kolónát. Minden sornál privát
   címnek kell állnia, `@evrst.hu`-nak **nem**. Ha valahol `@evrst.hu`-t látsz, annak a
   tagnak nincs `email_private`-ja (1. lépés).

Futtasd le a mail pre-flightot — ez egyben az elavult-login auditot is elvégzi:

```sh
docker compose exec backend php artisan mail:doctor
```

Zöld pipát kell látnod minden sornál, és `Mail path looks healthy.`-t a végén. Amit
ellenőriz: a mailer nem `log`, a Resend kulcs be van állítva **és a Resend el is fogadja**
(HTTP 200), a küldő domain `verified`, az `APP_URL` nem localhost, a queue nincs `null`-on,
a Discord webhook nem üres, és felsorolja, kinek nincs kiküldhető címe.

Ha a kulcsot nem akarod hálózaton ellenőrizni: `php artisan mail:doctor --no-api`.

Ha elavult login címet talál, javítsd **kiküldés előtt** — utána már kiadott credential.
A `mail:doctor` audit-részét kiegészíti ez:

```sh
docker compose exec backend php artisan org-email:realign
```

Ez összeveti minden org címet azzal, amit a csapattag **mostani neve** adna, és kiírja az
eltéréseket. Alapból csak jelez, nem ír; a `--apply` írja meg. Aki már belépett a jelenlegi
címével, azt kihagyja (kiadott credential), és külön felsorolja.

Ellenőrizd az admin fiókokat is:

```sh
docker compose exec backend php artisan user:role
```

Legalább egy `admin` kell, különben senki nem éri el a Users / Roles / Applications
oldalakat, és a bulk kiküldés sem indítható. A parancs nem nulla exit kóddal áll le, ha
egyetlen admin sincs.

## Ami tudatosan kimarad

- **Websupport postafiók / alias / Domain kosár.** Nem kell. Az `@evrst.hu`-ra küldött
  levél visszapattan, de semmi nem küld oda. Csak akkor kerül elő, ha egyszer azt
  akarod, hogy az `@evrst.hu` fogadni is tudjon — `org-email-logins.md` §3.4.
- **`MAIL_DELIVER_TO_ORG=true`.** Csak a fenti után.
- **Onshape** (`ONSHAPE_ACCESS_KEY` / `ONSHAPE_SECRET_KEY`) és **R2** feltöltés-tárolás
  (`FILESYSTEM_PUBLIC_DRIVER=s3`) — mindkettő üresen hagyható, a belépéshez nem kell.
  Az R2-höz lásd `r2-setup.md`.
- **`.github/workflows/deploy.yaml`** (Dokku, csak a SPA-t tolta). A verzió-ellenőrzését
  ma javítottam (`frontend/package.json`), de a compose stack kiváltotta ezt az utat —
  eldöntendő, hogy törlöd-e.
- **`deploy/fly/fly.toml`** — parkolt, és van benne egy megoldatlan probléma (a `worker`
  process group is futtatna migrate-et; a fájlban ott a figyelmeztetés). Ne deployolj
  vele anélkül.
